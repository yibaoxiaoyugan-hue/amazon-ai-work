# 亚马逊跨境电商 AI 工作台（amazon-ai-work）

> 面向亚马逊运营 / AI 产品经理作品集的单文件原型工作台。
> 在统一模拟数据源之上，覆盖「每日运营 → 产品表现 → 广告优化 → 单品分析」的运营分析闭环。

---

## 一、项目定位

一个**零后端、零构建、单文件**的跨境电商运营分析工作台原型。所有页面读同一套模拟数据源 `DS`（产品 / 订单 / 广告 / 库存 / Listing 一一对应），按未来接入 **Amazon SP-API / ERP / Excel / MCP** 的结构设计，便于后续真实数据替换与工程化。

当前所有数据均为**模拟数据**（详见「数据说明」），可直接打开预览，无需任何账号或网络。

---

## 二、核心功能

| 模块 | 页面 | 说明 |
| --- | --- | --- |
| **每日运营** | 每日数据 | 实时看板：店铺 / 站点 / 日期筛选，13 项核心指标，实时产品表现表（可点进单品分析），异常产品区 |
| | 每日关键词自然位分析 | 关键词自然排名追踪（读统一 DS） |
| | 每日关键词广告位分析 | 关键词广告位 / CPC / ACOS 追踪（读统一 DS） |
| | 每日竞品分析 | 竞品对标（读统一 DS） |
| **产品表现中心** | 所有 Listing 管理 | 父 ASIN / 子 ASIN 层级树、字段设置、库存详情弹窗、单品分析入口，默认筛在售 |
| | 所有 SKU 管理 | 内部供应链视角，按「系列 → 产品 → SKU」分组（如 Pocket 系列含 Pocket 3 / Pocket 4） |
| **广告优化中心** | 广告总览 | 9 项 KPI + 3 趋势 + 4 张表 + 异常洞察 |
| **单品分析** | 单品详情 | 6 个 Tab：数据总览 / 历史对比（按时间筛选）/ AI 分析 / 异常提醒 / 竞品对比 / 运营记录 |
| 数据中心 | 数据源 / Mock / 导入 | 统一数据层接入说明与模拟数据开关 |
| 目标管理 | 日 / 周 / 月目标与复盘 | 目标设定、进度、复盘、报告 |

### 关键设计约束（恒等口径，便于后续接真实数据）
- 销售额 = 订单数 × 售价
- 自然订单 + 广告订单 = 总订单
- ACOS = 广告花费 ÷ 广告销售额
- CVR = 订单数 ÷ Sessions
- 可售天数 = 库存 ÷ 近 7 日日均销量
- 库存滚动 = 昨日库存 + 入库 − 销量

## 三、技术栈

- **纯静态单文件**：`index.html`（HTML + 内联 CSS + 原生 JavaScript + 内联 SVG 图表，**无任何框架、无 CDN、无外部依赖**）。
- **运行时**：浏览器直接打开即可（无需 Node、无需打包、无需服务器）。
- **AI 分析（可选）**：在应用内「设置 / AI 配置」面板填写 Endpoint + Key 后调用真实大模型；未配置时自动回退为**本地数据计算引擎**，全程离线可用。
- **测试**：开发期使用 Playwright（headless Edge）做 DOM 断言冒烟测试。

> 无 `package.json` / 无 `node_modules` / 无构建步骤 —— 这是有意为之，方便作品集评审者零门槛打开。

## 五、数据说明（重要）

- **全部为模拟数据**，不含任何真实店铺、真实订单、真实用户或公司敏感信息。
- 商品目录基于**公开的 DJI 产品 ASIN**（Osmo Action 3/4/5 Pro、Pocket 3 / Pocket 4、Osmo 360 等）作为示例骨架；其销量、Session、库存、排名、CPC 等**指标均为程序生成的模拟值**，仅用于演示。
- 部分关键词 / 竞品页面保留了早期开发的占位常量（如 `BOXXXX001` 风格的示例 ASIN 与 `comica microphone` 等样例关键词），同样为虚构占位，不构成真实业务数据。
- 统一管理入口为全局 `DS`（由 `genData()` 生成），后续接入真实 Amazon API / ERP 时只需替换该数据层，页面逻辑不变。

## 六、本地运行

**方式一：直接打开（最简单）**
双击 `index.html`，或在浏览器中打开文件即可。纯模拟数据下无需联网。

**方式二：本地静态服务器（推荐，避免个别浏览器对 file:// 的限制）**
```bash
# 任选其一
npx serve .
# 或
python -m http.server 8080
# 然后访问 http://localhost:8080/index.html
```

**可选 · 开启 AI 分析**
在应用内「设置 / AI 配置」中填写：
- Endpoint（如 `https://api.openai.com/v1/chat/completions`）
- Key（你自己的接口密钥）
- Model
未填写时，单品分析的 AI 模块会自动回退为本地数据计算结论，不报错、不虚构。

## 七、部署

因为是纯静态单文件，可直接托管到任意静态平台：

- **GitHub Pages**：仓库根目录 `index.html` 即为入口，开启 Pages 后自动可访问。
- **Vercel / Netlify**：连接仓库，构建命令留空，发布目录设为仓库根。
- 也可直接把 `index.html` 丢到任意对象存储 / Nginx。

---

## 八、安全与隐私

- 仓库内**不含任何真实 API Key、数据库密码、访问令牌或个人/公司敏感数据**（已扫描确认）。
- AI Key 仅由使用者在应用界面内填写，存于浏览器内存，**不会写入代码或 Git 历史**。
- 若仓库设为 **Public**：因全部为模拟数据且无密钥，公开无敏感泄露风险；但 AI 配置属于使用者本地行为，密钥不会被提交。
